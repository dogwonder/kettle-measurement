# Shared capability corpus

One set of typed source facts rendered into more than one document
kind, so the same reading capabilities can be asked of a model across
layouts and judged by one scorer (plan work package 4; #595, #432).

`slice-01.json` is generated by `kettle-examples`
(`python -m synth_letters corpus`, `synth_letters/corpus.py`) and
committed here; its `provenance` carries the generating revision, a
digest of the facts, relations and cases, and `synthetic: true`. The
generator's own tests check the committed copy against a fresh build,
so a stale copy fails there. Regenerate by running the generator; never
edit the JSON by hand.

## What a slice holds

- **facts** — typed values with a stable id and a status: `stated`,
  `absent`, `ambiguous` or `unsupported`. A `role` says what the fact
  is for a reader (the base a period counts from, a distractor beside
  the sum asked for). Truth is authored, never recovered by the
  production parser.
- **relations** — `selected-over-distractor` pairs naming the fact a
  correct reading chooses and the true fact printed beside it.
- **cases** — one per document kind. Each carries the passages, the
  spans binding every rendered fact to the exact text in its passage,
  and the asks: which passage makes each, its kind, whether it is an
  obligation, its fields bound to fact ids, and the deadline as the
  document words it.

Slice 01 is a council tax demand as a letter and as a statement: a
dated letter's base, a 14-day payment with the instalment beside the
annual total, an appointment with a time and a place, a reference to
quote, a conditional ask the document cannot settle, and no time of day
for the payment.

## How it is scored

`crates/runner/src/eval/corpus.rs` keeps three records apart for every
ask: what the document states, the **raw** proposal the model made
(readings as the wire carries them) and the **verified** output the
pipeline finally shows. Each selected field is judged on both sides as
`Correct`, `Wrong`, `Missing`, `Uncertain` or `Unsupported`. A pack's
`Selection` names the fields it judges; the letter pack's is kind,
party, deadline and amount, so a right time proposed to it is
`Unsupported` on both sides and never a pass. The verified output
carries no time, place or reference today and says `Unsupported`
whatever the selection. Missed asks, invented asks, evidence
attachment and declared uncertainty are counted separately, and
whole-item correctness sits beside the field results.

`crates/runner/tests/corpus_slice.rs` establishes the scorer's
behaviour with fixed proposals and no weights, verifying each proposal
through the real `reading::check` and timeline. What it found is in
`evals/capabilities/fourth-batch.md`.

## Limits

Two cases and two obligations are a scorer, not a denominator. No
model has read the slice; `model_reading` coverage for every form in
the inventory is still `not-measured`. The verified column exercises
the boundary on `main` (v18); #628's deadline structure is not here.
