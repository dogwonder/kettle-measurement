# Shared capability corpus

One set of typed source facts rendered into more than one document
kind, so the same reading capabilities can be asked of a model across
layouts and judged by one scorer (plan work package 4; #595, #432).

`slice-01.json` is generated by `kettle-examples`
(`python -m synth_letters corpus`, `synth_letters/corpus.py`) and
committed here; its `provenance` carries the generating revision, a
digest of the facts, relations and cases, and `synthetic: true`. The
generator's own tests check the committed copy against a fresh build,
so a stale copy fails there. Regenerate by running the generator; never
edit the JSON by hand.

## What a slice holds

- **facts** — typed values with a stable id and a status: `stated`,
  `absent`, `ambiguous` or `unsupported`. A `role` says what the fact
  is for a reader (the base a period counts from, a distractor beside
  the sum asked for). Truth is authored, never recovered by the
  production parser.
- **relations** — `selected-over-distractor` pairs naming the fact a
  correct reading chooses and the true fact printed beside it.
- **cases** — one per document kind. Each carries the passages, the
  spans binding every rendered fact to the exact text in its passage,
  and the asks: which passage makes each, its kind, whether it is an
  obligation, its fields bound to fact ids, and the deadline as the
  document words it.

Slice 01 is a council tax demand as a letter and as a statement: a
dated letter's base, a 14-day payment with the instalment beside the
annual total, an appointment with a time and a place, a reference to
quote, a conditional ask the document cannot settle, and no time of day
for the payment.

## How it is scored

`crates/runner/src/eval/corpus.rs` keeps three records apart for every
ask: what the document states, the **raw** proposal the model made
(readings as the wire carries them) and the **verified** output the
pipeline finally shows. Each selected field is judged on both sides as
`Correct`, `Wrong`, `Missing`, `Uncertain` or `Unsupported`. A pack's
`Selection` names the fields it judges; the letter pack's is kind,
party, deadline and amount, so a right time proposed to it is
`Unsupported` on both sides and never a pass. The verified output
carries no time, place or reference today and says `Unsupported`
whatever the selection. Missed asks, invented asks, evidence
attachment and declared uncertainty are counted separately, and
whole-item correctness sits beside the field results.

`crates/runner/tests/corpus_slice.rs` establishes the scorer's
behaviour with fixed proposals and no weights, verifying each proposal
through the real `reading::check` and timeline. What it found is in
`evals/capabilities/fourth-batch.md`.

## Limits

The original two-case slice establishes the scorer. The additional 33-case
`diagnostic-01.json` selection adds named distinctions, not a statistically
sufficient harm-ceiling denominator. No model has read these diagnostic cases; `model_reading` coverage for every form in
the inventory is still `not-measured`. The verified column exercises
the boundary on `main` (scoring 19), including #628's authored deadline
structure and base reading. The corpus tests use controlled proposals;
the `kettle corpus` command now connects actual execution and recordings.
Controlled responses establish the adapter, not model accuracy.

## Execute a diagnostic slice

From the repository root, a deterministic floor needs no weights:

```sh
cargo run -p kettle -- corpus --no-model --out evals/runs/corpus-floor-01
```

Every case in `--corpus` (default `slice-01.json`) runs through the pack's
ordinary obligations pipeline. The default input is the case's passages
rendered as text. `--out` must be new: existing evidence is never replaced.
The report uses its own `corpus-fields-v4` scoring identity; it does not
write pack baselines or tiers, or change the pack's scoring version.

For a scheduled measurement, replace `--no-model` with `--model` and a
local GGUF path, optionally naming `--context` and `--sidecar-binary`.
`--mock-port` instead uses a controlled loopback endpoint and records that
route without inventing a model identity. CLI integration tests demonstrate
that route, including wrong sums, omitted asks, invented asks and retries:

```sh
cargo test -p kettle --test corpus_cli
```

Replay a recorded model or controlled-endpoint run into another new directory:

```sh
cargo run -p kettle -- corpus --replay evals/runs/corpus-run-01 \
  --out evals/runs/corpus-rescore-01
```

Replay requires exact generation payloads and refuses legacy prompt-only
recordings. Changed source or schema requests cannot borrow old answers.
Changed truth can rescore compatible answers and gets a new corpus digest.
There is no score cache in this diagnostic path: scores are always recomputed.
Generation machine, model/weights, sidecar/device and runtime provenance are
preserved separately from the machine and executable doing the scoring.

### Acquired inputs and page groups

`--bindings bindings.json` substitutes files for selected cases. Paths are
relative to the bindings file; omitted cases use generated text. For example:

```json
{
  "slice01-letter": {
    "inputs": {"letter": ["front.txt", "back.txt"]}
  }
}
```

This uses the fixture filename/list syntax and the pack's file grouping and
limits. Recordings include ordered input hashes and actual document/page/
passage coordinates. Source passages align to an ordered sequence of acquired
segments; a split sign-off is supported. Missing or ambiguous alignment,
or a fact/ask that cannot map to one segment, produces an acquisition error
and an explicitly unscored case. It is never repaired using a gold value or
reported as an ordinary model omission. Independent documents require a
manifest declaring `documents`; the shipped letter role declares `pages`.

`report.json` retains every case, its raw proposal, verified output, claim
traces, diagnostics, exact exchanges and field scores. Malformed or unpaired
answers remain visible alongside the scored ask denominator. The raw score
uses final decision candidates; earlier attempts remain in traces/exchanges,
so retries do not multiply the truth asks. Acquisition/execution failures
remain outside the field-score denominator and increment `unscored_cases`.
Exit 2 means one or more cases could not be scored, or configuration/recording
failed. Exit 0 means the diagnostic completed, not that the model passed.

Money scoring interprets GBP/£, EUR/€ and explicit USD, preserving signs and
decimal magnitude. A bare number, `$` without a currency code, malformed
grouping or another unsupported notation stays `Unsupported`, never Correct.
Raw amount scoring still checks the document's own wording independently.

## Inventory-linked selection

`diagnostic-01.json` is generated by `python -m synth_letters diagnostic`
in the sibling `kettle-examples` checkout. It selects 33 exact inventory
texts across all seven families: dates (8), money (5), obligations (8),
parties/place/reference (4), relationships (4), format (2) and time (2).
There are 28 positive asks and seven explicit no-obligation sites, including
completed/cancelled/conditional asks. Two tasks can share one sentence or
occupy separate bullets. Relations distinguish instalment/total,
sender/recipient and deadline/past-event values. A bare total without an
instruction to pay is deliberately outside this obligations selection.

The selection is named `reading-diagnostic-01`, purpose `diagnostic`,
exposure `development`. Each case pins its inventory id, file digest,
source document and narrow field scope. The command validates those links
against `--inventory-dir` (default `evals/capabilities`) before execution.
Changed inventories require regeneration. No challenge selection is accepted
by this command; independent authoring and the holdout workflow remain slice 4.

```sh
cargo run -p kettle -- corpus --corpus evals/corpus/diagnostic-01.json \
  --no-model --out evals/runs/diagnostic-floor-01
```

The letter pack scores kind, party, deadline and amount. Four selected
cases concern time, place or reference; their coverage scope remains
unsupported even if the pack answers other fields correctly. The 29
supported scopes can become measured attempts only through compatible
recorded model evidence, checked by `scripts/capability-coverage.py`.
A wrong answer is still an attempted measurement, never a capability pass.
All 112 inventory cases currently remain unmeasured by a model.

Corpus scoring v3 judges copied unresolved deadline wording independently
of whether a date can be derived. `deadline_at` identifies the raw phrase's
passage, separately from the resolved fact's span: a pointer stays in the
ask prose while its date stays in the table; bullets may share a printed
deadline above them. Explicit `negative_sites` count inventions on authored
no-obligation passages. A zero there does not establish that a model was
asked; recorded exchanges establish attempted measurement.

Independent challenge families, equivalent PDF/photo inputs and fresh model
comparisons remain in `plan.md`. No prompt, pack ceiling, baseline or tier
has changed in this slice.
